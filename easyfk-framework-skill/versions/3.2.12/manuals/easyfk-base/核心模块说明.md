## 一、项目概述

`easyfk-base` 是 EasyFK 框架的基础模块集合，提供了一整套微服务/单体应用开发所需的基础设施能力。框架采用分层模块化设计，涵盖核心工具、Web 层、服务层、数据访问层、远程调用、缓存、权限、网关、线程池、消息队列、日志、序列化等基础功能，开发者可按需引入相应模块快速搭建业务系统。

## 五、各模块详细说明

### 5.1 easyfk-core — 核心基础模块

框架的基础层，被所有其他模块依赖。

| 功能 | 说明 |
|------|------|
| 统一响应封装 | `ResponseResult<T>`，标准化 API 响应格式（code、msg、data、traceId） |
| 异常处理 | `BusinessException`、`ValidateException`，支持错误码与国际化 |
| 上下文管理 | `UserDataContext`（ThreadLocal）、`TraceIdContext`（InheritableThreadLocal） |
| DTO 体系 | `SearchRequest`（查询请求）、`PageResult`（分页结果）、`LoginUser`、`UserData` 等 |
| 注解体系 | `@PrimaryKey`、`@PrimaryField`、`@SingleUniqueField`、`@CombUniqueField`、`@BetweenField` 等 |
| 构建器 | `RRBuilder`、`BEBuilder`、`PRBuilder`、`SRPBuilder` 等，简化对象创建 |
| 工具类 | `ReflectUtil`（反射+缓存）、`EmptyUtil`（空值判断）、`FunctionExecutor`（函数式执行）、`I18NUtil`（国际化）等 |

**主要依赖**: Spring Boot Starter、Jackson、Fastjson2、Hutool、MapStruct Plus、Swagger Annotations

**技术特点**:
- `BusinessException` 重写 `fillInStackTrace()` 返回空栈，避免业务异常时生成完整堆栈的性能开销
- `TraceIdContext` 基于 `InheritableThreadLocal`，支持父子线程间自动传递追踪 ID
- `ReflectUtil` 内置字段缓存（`ConcurrentHashMap`），避免重复反射带来的性能损耗
- `FunctionExecutor` 提供函数式编程风格的条件分支、空值处理和异常处理，减少样板代码
- DTO 体系采用泛型设计 + Builder 模式，`SearchRequest<T>` 支持 like、in、not、range 等多种查询条件的类型安全构建
- 国际化支持：`I18NUtil` + `BaseErrorEnum` 实现错误消息的多语言输出

### 5.2 easyfk-log — 日志模块

可插拔的日志实现模块，按需引入其中一个子模块即可切换日志框架。

| 子模块 | 说明 |
|--------|------|
| **log-logback** | 基于 Logback 实现，依赖 `spring-boot-starter-logging` + `logstash-logback-encoder`（支持 JSON 格式日志） |
| **log-log4j2** | 基于 Log4j2 实现，依赖 `spring-boot-starter-log4j2` |

**技术特点**:
- 可插拔设计：通过子模块隔离不同日志框架的依赖，切换日志实现只需更换引入的子模块，无需修改业务代码
- log-logback 集成 `logstash-logback-encoder`，原生支持 JSON 结构化日志输出，便于 ELK 等日志平台采集
- 依赖排除策略：log-logback 排除 Log4j 相关依赖，避免日志框架冲突

---

### 5.3 easyfk-repository — 数据访问层模块

统一的数据访问抽象层，定义 Repository 接口与查询条件构建器。

| 功能 | 说明 |
|------|------|
| `IBaseRepository<T, PK>` | 基础 Repository 接口，提供完整 CRUD 操作 |
| `SearchCondition` | 查询条件封装（like、equals、in、range、分页、排序、自定义 SQL） |
| `SCBuilder<T>` | 查询条件链式构建器，支持 Lambda 表达式 |
| `RepositoryUtil` | 保存、删除、唯一性校验工具 |
| `ConditionUtil` | 将 `SearchRequest` 转换为 `SearchCondition` |
| `@AutoUpdateTime` | 自动更新时间注解 |
| `@DefaultValueOnSave` | 保存时自动填充默认值注解 |
| `DbTypeEnum` | 支持 MySQL、MariaDB、Oracle、PostgreSQL、SQL Server、DB2、H2 等 |

**依赖**: easyfk-core

**技术特点**:
- 纯接口抽象设计：`IBaseRepository<T, PK>` 不绑定任何 ORM 框架（如 MyBatis、JPA），上层可自由选择持久化实现
- `SCBuilder` 采用 Java Record 类型 + 链式 API，支持 Lambda 表达式（`EFunction<T, ?>`）引用实体字段，避免硬编码字符串
- 多数据库兼容：`DbTypeEnum` 覆盖 MySQL、Oracle（11g/12c+）、PostgreSQL、SQL Server、DB2、H2 等主流数据库
- 注解驱动的持久化增强：`@DefaultValueOnSave` 支持 UUID、雪花 ID、日期时间等多种默认值类型，自动在保存时填充
- `RepositoryUtil` 内置单字段/组合字段唯一性校验，支持排除自身的更新场景校验
- `ConditionUtil` 自动将前端传入的 `SearchRequest` 转换为 `SearchCondition`，统一处理分页、排序、模糊查询、区间查询

### 5.4 easyfk-cache — 缓存接口模块

定义统一的缓存服务接口，具体实现由业务项目提供（如 Redis）。

| 核心接口 | 方法 |
|----------|------|
| `ICacheService` | `cacheObject` / `queryByKey` / `removeKey` / `existKey` / `expireKey` / `getKeyExpire` / `getSetCountByKey` |

**依赖**: easyfk-core（compileOnly）

**技术特点**:
- 纯接口定义：`ICacheService` 不绑定任何缓存实现（如 Redis、Caffeine），通过 `compileOnly` 依赖避免传递性耦合
- 支持命名空间隔离：接口方法支持按 key 前缀区分不同业务域的缓存数据
- 统一缓存抽象：覆盖对象缓存、过期管理、存在性检查、集合操作等常用缓存场景

---

### 5.5 easyfk-authority — 权限管理模块

基于注解的权限控制体系，提供用户认证与权限资源管理。

| 功能 | 说明 |
|------|------|
| 权限注解 | `@AuthResource`（权限资源）、`@LoginResource`（登录资源）、`@ResourceController`（资源控制器） |
| `IAuthResourceApi` | 权限资源 API（资源列表、URI 安全级别检查、批量保存） |
| `UserDataManager` | 用户数据管理器（权限缓存、登录/登出、权限验证） |
| 安全级别 | `LOGIN`（仅需登录）、`AUTHORITY`（需要权限）、`UNIMPEDED`（无需登录） |
| 用户类型 | `platform`（平台）、`agent`（代理）、`merchant`（商户）、`customer`（客户） |
| 资源类别 | `menu`（菜单）、`action`（功能）、`normal`（普通） |

**依赖**: easyfk-core、easyfk-cache、service-api

**技术特点**:
- 声明式权限定义：通过 `@AuthResource`、`@LoginResource`、`@ResourceController` 注解在 Controller 方法上声明权限，启动时自动扫描注册
- 三级安全模型：`UNIMPEDED`（公开）→ `LOGIN`（登录即可）→ `AUTHORITY`（需要具体权限），灵活控制接口访问
- 权限缓存自动续期：当缓存剩余时间 ≤ 600 秒时自动延长 10 分钟，减少频繁登录的用户体验问题
- 多租户/多平台支持：通过 `typeFlag`、`defaultFlag` 实现资源的平台级分类，`UserTypeEnum` 区分平台、代理、商户、客户四种用户类型
- 树形权限结构：资源支持父子关系，`UserAuthResources` 以树形结构组织权限资源
- 超级管理员机制：`supperUser` 标志跳过权限校验

### 5.6 easyfk-service — 服务层模块

#### 5.6.1 service-api — 服务接口定义

| 接口 | 说明 |
|------|------|
| `IBaseService<T, PK, R>` | 基础服务接口（queryById、queryList、queryByPage、save、delete 等） |
| `IBaseApi<T, PK, R>` | 基础 API 接口（含优化查询 queryByIdOptimize） |
| `IBaseFluxService<T, R>` | Flux 服务接口（无主键场景） |
| `IBaseFluxApi<T, R>` | Flux API 接口 |

**依赖**: easyfk-core

#### 5.6.2 service-base — 服务层基础实现

| 类 | 说明 |
|----|------|
| `BaseApiServiceImpl` | `IBaseApi` 的抽象实现，委托给 `IBaseService` |
| `UserDataFiltrationUtil` | 用户数据过滤工具（SaaS 数据隔离、权限过滤） |
| `ServiceUtil` | 保存/删除/插入操作封装 |
| `SearchRequestUtil` | 查询请求条件添加工具 |

**依赖**: service-api、easyfk-core、easyfk-repository、easyfk-authority

**技术特点**:
- 接口与实现分离：`service-api` 仅定义接口，`service-base` 提供实现，消费方只需依赖 api 模块
- 泛型模板设计：`IBaseService<T, PK, R>` 通过三泛型参数（实体、主键、请求）适配不同业务模型，一套代码覆盖所有 CRUD 场景
- 双模式接口：标准模式（`IBaseService`，含主键）和 Flux 模式（`IBaseFluxService`，无主键），适配关系表/流水表等不同场景
- SaaS 数据隔离：`UserDataFiltrationUtil` 自动根据当前用户身份注入数据过滤条件，实现多租户数据隔离
- 委托模式：`BaseApiServiceImpl` 将 API 调用委托给 `IBaseService`，自动处理分页默认值（默认第 1 页，每页 20 条）

### 5.7 easyfk-web — Web 层模块

#### 5.7.1 web-simple — 基础 Web 启动器

提供 Spring Boot Web 基础环境，使用 **Undertow** 作为 Web 服务器（替代 Tomcat）。

**依赖**: spring-boot-starter-web（排除 Tomcat）、spring-boot-starter-undertow、easyfk-core

#### 5.7.2 web-base — JWT 与上下文管理

| 类 | 说明 |
|----|------|
| `JwtManager` | JWT 令牌创建与解析 |
| `ContextDataManager` | 上下文数据管理（用户数据、TraceId、请求头） |
| `JwtProperties` | JWT 配置（密钥、过期时间） |

**依赖**: easyfk-core、easyfk-authority

#### 5.7.3 web-common — Web 通用配置

| 类 | 说明 |
|----|------|
| `SecurityProperties` | 安全配置（验签、防重放） |
| `InterceptProperties` | 拦截器配置（过滤路径、权限拦截等级） |
| `CorsProperties` | CORS 跨域配置 |

**依赖**: easyfk-core、spring-web、web-base

#### 5.7.4 web-prd — 生产环境 Web 配置

适用于对外暴露的生产环境应用，功能最全。

| 功能 | 类 |
|------|----|
| 请求过滤 | `RequestBaseFilter`（签名验证、防重放、请求头处理） |
| 拦截器 | `LocalInterceptor`（登录验证、权限验证） |
| 异常处理 | `PrdExceptionHandler`（全局统一异常处理） |
| AOP 切面 | `ControllerAspect`（Controller 日志记录） |
| CORS | 跨域支持 |
| Jackson | 时间格式、空值处理序列化配置 |
| 资源初始化 | `InitResourceRunner`（启动时自动注册权限资源） |

**依赖**: web-simple、web-common

**web-prd 技术特点**:
- 接口安全防护：MD5 签名验证 + Nonce 防重放攻击，支持动态签名密钥轮换
- 分层过滤链：Filter（安全验签）→ Interceptor（登录/权限）→ AOP（日志），职责清晰
- 启动时资源注册：`InitResourceRunner` 在应用启动时自动扫描 `@AuthResource` 注解并批量注册到权限系统
- Jackson 深度定制：自定义时间格式转换器、空值序列化策略，统一前后端数据格式

#### 5.7.5 web-micro — 微服务环境 Web 配置

适用于微服务内部调用场景，配置简化（无安全验签）。

| 功能 | 类 |
|------|----|
| 请求过滤 | `RequestBaseFilter`（仅处理请求头与 TraceId） |
| 异常处理 | `MicroExceptionHandler` |
| Jackson | 序列化配置 |

**依赖**: web-simple、web-common

**Web 模块整体技术特点**:
- 场景化拆分：web-prd（生产/完整安全）和 web-micro（微服务/轻量）两套配置，按部署场景选择
- Undertow 替代 Tomcat：更低的内存占用和更高的并发性能
- Spring Boot 自动配置：所有配置类通过 `@AutoConfiguration` 实现零代码接入
- 上下文全链路传递：请求头、用户数据、TraceId 通过 ThreadLocal 在 Filter → Interceptor → Controller → Service 全链路可用

### 5.8 easyfk-remote — 远程调用模块

提供统一的远程调用抽象，支持 Dubbo 和 Spring Cloud 两种 RPC 方式。

#### 5.8.1 remote-dubbo — Dubbo 远程调用

| 类/接口 | 说明 |
|---------|------|
| `IDubboBaseRemote<T, PK, R>` | Dubbo 远程服务接口 |
| `DubboBaseRemoteImpl` | 服务提供者实现（调用本地 Service） |
| `DubboBaseApiRemoteImpl` | 服务消费者实现（通过 @DubboReference 调用远程） |

**依赖**: easyfk-remote（父模块）、Apache Dubbo 3.3.5

#### 5.8.2 remote-cloud — Spring Cloud 远程调用

| 类/接口 | 说明 |
|---------|------|
| `IBaseRemote<T, PK, R>` | REST 远程服务接口（Spring MVC 注解） |
| `BaseRemoteImpl` | 服务提供者实现 |
| `BaseApiRemoteImpl` | 服务消费者实现 |

**依赖**: easyfk-remote（父模块）、spring-web

**父模块依赖**: easyfk-core、service-api

**技术特点**:
- RPC 框架无感切换：统一的 `IBaseApi` / `IBaseService` 接口，底层 Dubbo 或 Spring Cloud 实现对业务层完全透明
- 适配器模式：`*ApiRemoteImpl`（消费者）和 `*RemoteImpl`（提供者）通过适配器模式桥接不同协议
- compileOnly 依赖：Dubbo/Spring Web 均为 `compileOnly`，不会传递到业务项目，按需引入
- 服务提供者/消费者双角色：同一接口既可作为远程服务暴露（Provider），也可作为远程调用客户端（Consumer）
- Flux 版本支持：针对无主键的流水表/关系表场景提供简化的远程接口

### 5.9 easyfk-gateway — API 网关模块

基于 Spring Cloud Gateway 的统一网关过滤器。

| 功能 | 说明 |
|------|------|
| 请求头处理 | 解析与传递签名、Token、设备号等 |
| 签名校验 | MD5 签名验证，支持动态密钥 |
| 防重放 | Nonce 校验机制 |
| 权限校验 | 登录与权限验证 |
| 扩展点 | `ICustomGatewayFilter`、`IExtendGatewayFilter` 自定义过滤器接口 |

**依赖**: easyfk-core、web-common、easyfk-authority、spring-cloud-starter-gateway

**技术特点**:
- 基于 Spring Cloud Gateway 的响应式过滤链：`GlobalFilter` + `Ordered` 实现统一的请求拦截
- 与 web-prd 安全能力复用：共享签名校验、防重放、权限验证逻辑，保持网关与应用层安全策略一致
- 双扩展点设计：`ICustomGatewayFilter`（自定义过滤逻辑）和 `IExtendGatewayFilter`（扩展过滤链），支持业务层灵活定制
- 请求头透传：自动将签名、Token、设备号、TraceId 等信息传递到下游微服务

### 5.10 easyfk-thread — 线程池管理模块

提供多种线程池配置、动态调整与监控能力。

| 功能 | 说明 |
|------|------|
| 线程池类型 | 通用任务、异步任务、定时任务、I/O 密集型、CPU 密集型、重试专用 |
| 动态调整 | `ThreadPoolMonitor` 根据负载自动扩容/缩容 |
| 监控 | 活跃线程、队列大小、利用率等指标采集 |
| 重试机制 | `RetryExecutor` 支持同步/异步重试、多种退避策略（线性、指数） |

**依赖**: easyfk-core（compileOnly）

**技术特点**:
- 场景化线程池：按任务特征（通用、I/O 密集型、CPU 密集型、定时、重试）预置不同配置的线程池，避免线程资源竞争
- 动态调参：`ThreadPoolMonitor` 实时监控线程池负载，根据利用率自动扩容/缩容核心线程数和队列大小
- 监控统计：采集活跃线程数、队列深度、利用率、任务完成数等指标，支持同步/异步两种监控模式
- 重试执行器：`RetryExecutor` 支持线性退避、指数退避策略，通过信号量控制并发重试数量，防止雪崩
- compileOnly 设计：不强制传递依赖，业务项目可选择性引入

### 5.11 easyfk-queue — 消息队列模块

#### queue-disruptor — Disruptor 高性能队列

| 功能 | 说明 |
|------|------|
| `IIngestQueue<T>` | 队列接口（阻塞/非阻塞入队） |
| `DisruptorIngestQueue` | 基于 RingBuffer 的队列实现 |
| `IngestQueueManager` | 队列管理器（门面模式，延迟初始化） |
| 自动配置 | 自动发现 `Processor` Bean 并创建队列 |
| 等待策略 | BLOCKING、YIELDING、BUSY_SPIN |
| 生产者模式 | 单生产者 / 多生产者 |

**依赖**: easyfk-core、LMAX Disruptor 4.0.0

**技术特点**:
- 基于 LMAX Disruptor RingBuffer：无锁设计，单线程百万级 TPS，远超传统 `BlockingQueue`
- 多种等待策略：BLOCKING（低 CPU 占用）、YIELDING（低延迟）、BUSY_SPIN（极致性能），按场景选择
- Spring Boot 自动装配：自动发现 `Processor` Bean 并创建对应队列，零配置接入
- 门面模式 + 延迟初始化：`IngestQueueManager` 延迟初始化避免 Spring Bean 循环依赖问题
- 优雅关闭：`ShutdownManager` 确保应用停止时队列中的消息处理完毕
- 批量发送与重试：`sendBatch`、`sendWithRetry` 满足高可靠性场景

### 5.12 easyfk-serializer — 序列化模块

#### 5.12.1 serializer-base — 序列化接口定义

| 类/接口 | 说明 |
|---------|------|
| `SerializerClassRegister` | 序列化类注册器接口 |
| `SerializerProperties` | 序列化配置属性 |
| `SerializerInitializer` | 序列化器初始化器 |

**依赖**: easyfk-core（compileOnly）

#### 5.12.2 serializer-fory — Apache Fory 序列化实现

| 类/接口 | 说明 |
|---------|------|
| `ForySerializer` | Fory 序列化器（Java 内部序列化 + 跨语言 XLANG 序列化） |
| `ForySerializerClassRegister` | 类注册器实现 |

**依赖**: serializer-base、Apache Fory 0.14.1

**技术特点**:
- 接口与实现分离：`serializer-base` 定义抽象接口，`serializer-fory` 提供具体实现，可扩展其他序列化框架
- 双模式序列化：Java 内部序列化（高性能）+ XLANG 跨语言序列化（多语言互通），一个类库满足两种场景
- Holder 延迟初始化：`ForySerializer` 使用 Holder 模式延迟创建 Fory 实例，避免启动时的初始化开销
- 线程安全：底层使用 `ThreadSafeFory`，多线程环境下无需额外同步
- 类注册机制：通过 `SerializerClassRegister` 接口预注册序列化类，配合 `@SerializableClass` 注解实现自动扫描注册
- Spring Boot 自动配置：通过 `@AutoConfiguration` 实现开箱即用

## 六、使用指南

### 单体应用

引入以下模块即可快速搭建单体应用：

```groovy
implementation 'com.mcst:easyfk-core:3.2.12'
implementation 'com.mcst:web-prd:3.2.12'
implementation 'com.mcst:service-base:3.2.12'
implementation 'com.mcst:easyfk-repository:3.2.12'
implementation 'com.mcst:log-logback:3.2.12'
```

### 微服务应用

- **网关服务**: 引入 `easyfk-gateway`
- **业务服务（对外）**: 引入 `web-prd` + `service-base` + `easyfk-repository`
- **业务服务（内部）**: 引入 `web-micro` + `service-base` + `easyfk-repository`
- **远程调用**: 按需引入 `remote-dubbo` 或 `remote-cloud`

### 可选能力

- **高性能队列**: 引入 `queue-disruptor`
- **线程池管理**: 引入 `easyfk-thread`
- **序列化**: 引入 `serializer-fory`

## 七、版本管理

- 所有模块统一版本号 `3.2.12`
- 依赖版本通过 `easyfk-dependencies` BOM 统一管理
- 注解处理器统一配置 MapStruct Plus 空值映射策略为 `IGNORE`
