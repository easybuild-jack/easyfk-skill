# 监控指南（Metrics / Observability）

面向 **业务工程师 + SRE**。讲清楚这套 SDK 暴露哪些指标、怎么用最少的代价接到
Prometheus / Grafana / Datadog，以及该对哪些指标告警。

> TL;DR：引入 `aeron-metrics-micrometer` + 任意 Micrometer `MeterRegistry`，**零代码**拿到
> 发送 / 接收 / 背压 / 丢弃 / 去重 / 端到端延迟直方图 / outbox 积压 等全套指标。Spring Boot 下
> 连 bean 都自动接好。

---

## 1. 架构：3 个 SPI + 1 个开箱适配

SDK 核心**不绑定**任何监控框架，只在热路径埋了三个指标钩子接口（默认 `noop()`，零开销）：

| SPI | 模块 | 覆盖 |
|---|---|---|
| `ProducerMetrics` | `aeron-common` | 发送 / 背压 / 丢弃 / 错误 |
| `ConsumerMetrics` | `aeron-common` | 接收 / 去重 / 错误 / dispatch 丢弃 / **端到端延迟** |
| `OutboxMetrics` | `aeron-producer-outbox` | WAL 落盘 / 转发 / 重试 / 崩溃恢复 / **积压** |

可选模块 **`aeron-metrics-micrometer`** 提供这三个 SPI 的 Micrometer 实现，把指标桥接到任意
`MeterRegistry`，从而落到 Prometheus / OTLP / Datadog / CloudWatch / SimpleMeterRegistry。

```
你的代码 → AeronProducer/Consumer/OutboxProducer
                     │  (调用 SPI 钩子)
                     ▼
        Micrometer*Metrics  ──►  MeterRegistry  ──►  Prometheus / Grafana / Datadog ...
```

## 2. 快速接入

### 2.1 Spring Boot（推荐，零代码）

```groovy
implementation 'com.mcst:aeron-metrics-micrometer'
implementation 'org.springframework.boot:spring-boot-starter-actuator'   // 提供 MeterRegistry + /actuator/prometheus
runtimeOnly    'io.micrometer:micrometer-registry-prometheus'            // 想出 Prometheus 格式
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,prometheus
# easyfk.config.aeron.metrics.enabled: true   # 默认即开，无需写
```

启动后 `AeronMetricsAutoConfiguration` 自动：检测到 classpath 有 `MeterRegistry` + 适配模块、
且容器里有 `MeterRegistry` bean，就注册 Micrometer 版 `ProducerMetrics` / `ConsumerMetrics`
并注入到自动装配的 producer / consumer。指标直接出现在 `GET /actuator/prometheus`。

- 关闭：`easyfk.config.aeron.metrics.enabled=false`。
- 覆盖：自定义 `@Bean ProducerMetrics` / `@Bean ConsumerMetrics` 会因 `@ConditionalOnMissingBean` 胜出。
- **不引适配模块**：autoconfig 静默跳过，SDK 走 noop，零开销、零传递依赖。

### 2.2 非 Spring（手动）

```java
MeterRegistry registry = /* PrometheusMeterRegistry / 你已有的 */;

AeronProducer producer = AeronProducer.builder()
        .driver(driver).config(cfg).codecRegistry(codecs)
        .metrics(new MicrometerProducerMetrics(registry))
        .build();

AeronConsumer consumer = AeronConsumer.builder()
        .driver(driver).config(cfg).codecRegistry(codecs)
        .metrics(new MicrometerConsumerMetrics(registry))
        .build();
```

### 2.3 Outbox（手动注入，两端通用）

Outbox 无论 Spring 与否都是手动接入，监控也手动传：

```java
OutboxMetrics m = new MicrometerOutboxMetrics(registry);
Producer p = OutboxProducer.wrap(delegate, outboxConfig, codecRegistry, idGenerator, m, true);
```

> 公共标签：三个适配类都有一个 `(registry, Tags commonTags)` 重载，可注入 `application` /
> `instance` / `driver` 等公共标签：`new MicrometerProducerMetrics(registry, Tags.of("app","md-gateway"))`。

## 3. 指标全清单

> 标签设计见 §4；下表「Prometheus 名」按 Micrometer 默认命名规约换算（`.`→`_`，counter 加 `_total`，
> Timer 出 `_seconds` 直方图）。

### 3.1 Producer（`aeron.producer.*`）

| 指标 | 类型 | 标签 | Prometheus 名 | 含义 |
|---|---|---|---|---|
| `aeron.producer.sent` | counter | `partition` | `aeron_producer_sent_total` | 成功写入 publication 的消息数 |
| `aeron.producer.sent.bytes` | counter | `partition` | `aeron_producer_sent_bytes_total` | 成功写入的 payload 字节累计 |
| `aeron.producer.backpressure.retries` | counter | `partition` | `aeron_producer_backpressure_retries_total` | 背压重试累计次数 |
| `aeron.producer.dropped` | counter | `partition` | `aeron_producer_dropped_total` | 按策略丢弃的消息数 |
| `aeron.producer.errors` | counter | `partition` | `aeron_producer_errors_total` | 编码 / 压缩 / 提交 / 路由异常数 |

### 3.2 Consumer（`aeron.consumer.*`）

| 指标 | 类型 | 标签 | Prometheus 名 | 含义 |
|---|---|---|---|---|
| `aeron.consumer.received` | counter | `group`,`partition` | `aeron_consumer_received_total` | 成功 dispatch 到 handler 的消息数 |
| `aeron.consumer.received.bytes` | counter | `group`,`partition` | `aeron_consumer_received_bytes_total` | payload 字节累计 |
| `aeron.consumer.latency` | timer | `group`,`partition` | `aeron_consumer_latency_seconds{_bucket,_count,_sum}` | **端到端延迟**（p50/p99/p99.9 直方图） |
| `aeron.consumer.duplicates` | counter | `group`,`partition` | `aeron_consumer_duplicates_total` | 被 deduper 抑制的重复消息数 |
| `aeron.consumer.errors` | counter | `group`,`partition` | `aeron_consumer_errors_total` | decode / dispatch / 解压 / 类型不匹配 异常数 |
| `aeron.consumer.dispatch.dropped` | counter | `group`,`partition` | `aeron_consumer_dispatch_dropped_total` | `RING_BUFFER_POOL` 队列满 / 已 close 丢弃数 |

### 3.3 Outbox（`aeron.outbox.*`，仅开启 outbox 时）

| 指标 | 类型 | 标签 | Prometheus 名 | 含义 |
|---|---|---|---|---|
| `aeron.outbox.persisted` | counter | — | `aeron_outbox_persisted_total` | 成功落盘进 WAL 的消息数 |
| `aeron.outbox.persisted.bytes` | counter | — | `aeron_outbox_persisted_bytes_total` | 落盘 payload 字节累计 |
| `aeron.outbox.forwarded` | counter | — | `aeron_outbox_forwarded_total` | 成功从 WAL 转发到 Aeron 的消息数 |
| `aeron.outbox.forward.retries` | counter | — | `aeron_outbox_forward_retries_total` | 转发瞬时失败重试次数 |
| `aeron.outbox.recovered` | counter | — | `aeron_outbox_recovered_total` | 崩溃恢复时重放转发的消息数 |
| `aeron.outbox.errors` | counter | — | `aeron_outbox_errors_total` | WAL / 转发链路异常数 |
| `aeron.outbox.backlog.bytes` | gauge | — | `aeron_outbox_backlog_bytes` | **WAL 已落盘未转发的积压字节（重点告警项）** |

## 4. 标签（维度）设计 —— 基数安全

适配实现**故意只按有界维度打标签**：

- Producer：`partition`（分片数有界）。
- Consumer：`group`（消费组，低基数）+ `partition`。
- Outbox：无标签（单转发器，全局聚合）。

**为什么不按 topic 打标签**：行情系统 topic 基数可能上千甚至上万，直接做标签会让 Prometheus
时间线爆炸（cardinality explosion），拖垮存储与查询。这是刻意的安全默认。

> 确实需要 topic 维度？自行实现对应 SPI（`ProducerMetrics` 等），在 Spring 下定义同类型 `@Bean`
> 即可覆盖默认适配（`@ConditionalOnMissingBean`）。务必自己控制 topic 基数。

`groupId` 为 `null` 时，`group` 标签值取 `"none"`（Micrometer 不允许 null 标签值）。

## 5. 端到端延迟（`aeron.consumer.latency`）怎么读

- 它是 producer 写入帧的时间戳与 consumer 收到时刻之差，用**墙钟**（`Instant.now()` epoch 纳秒，~µs 分辨率）相减。
- **同机 IPC / 同机 UDP**：两端同一系统时钟，差值是 **µs 级可信的真实单向延迟**，可作为 SLO。
- **跨主机**：精度受 NTP/PTP 时钟同步质量限制，只适合粗略观测；要精确跨机延迟需部署 PTP。负值（时钟回拨）会被**忽略不记**。
- 直方图：适配用 `Timer.publishPercentiles(0.5, 0.99, 0.999)` + `publishPercentileHistogram()`，
  Prometheus 端用 `histogram_quantile` 聚合算分位。
- 想关掉每条消息的延迟记录开销：用 `new MicrometerConsumerMetrics(registry, tags, /*recordLatency*/ false)`。

## 6. 推荐告警 & 看板（PromQL 示例）

**积压堆积（outbox 最关键）** —— 转发跟不上落盘，磁盘在涨：
```promql
aeron_outbox_backlog_bytes > 50 * 1024 * 1024        # >50MiB 持续即告警
```

**消息被丢弃** —— 背压策略在丢行情：
```promql
rate(aeron_producer_dropped_total[1m]) > 0
rate(aeron_consumer_dispatch_dropped_total[1m]) > 0  # 消费侧 worker 队列满
```

**错误率**：
```promql
rate(aeron_producer_errors_total[5m]) > 0
rate(aeron_consumer_errors_total[5m]) > 0
```

**端到端延迟 p99（仅同机可信）**：
```promql
histogram_quantile(0.99, sum by (le,group,partition) (rate(aeron_consumer_latency_seconds_bucket[5m])))
```

**背压压力**（重试在升）：
```promql
rate(aeron_producer_backpressure_retries_total[1m])
```

**吞吐**：
```promql
sum by (partition) (rate(aeron_producer_sent_total[1m]))
sum by (group)     (rate(aeron_consumer_received_total[1m]))
```

**去重命中**（dedup 窗口是否合理 / 是否有大量重发）：
```promql
rate(aeron_consumer_duplicates_total[5m])
```

## 7. 开销与取舍

- 计数器极轻量：每个钩子按 `partition`（consumer 还按 `group`）命中一次缓存的 `Counter`
  （`partition < 128` 时 `Integer` 装箱走 JDK 缓存，**稳态零分配**），不在每条消息上做 Tags 解析或字符串拼接。
- `aeron.consumer.latency` 的 `Timer.record` 维护滚动直方图，比纯计数稍重；极端吞吐下可用上面的 `recordLatency=false` 关掉。
- **极致低延迟关键路径**：任何 metrics 都有成本，可直接用 `ProducerMetrics.noop()` / `ConsumerMetrics.noop()`，或不引适配模块。

## 8. 自定义实现（不依赖 Micrometer）

三个 SPI 都是普通接口，可自行对接 OTel / StatsD / 日志 / 自研系统：

```java
public final class MyProducerMetrics implements ProducerMetrics {
    @Override public void onSent(String topic, int partition, int payloadBytes) { /* ... */ }
    @Override public void onBackpressure(String topic, int partition, int retries) { /* ... */ }
    @Override public void onDropped(String topic, int partition) { /* ... */ }
    @Override public void onError(String topic, int partition, Throwable error) { /* ... */ }
}
AeronProducer.builder().metrics(new MyProducerMetrics()).build();
```

仓库另自带 `InMemoryProducerMetrics` / `InMemoryConsumerMetrics`（全局累加，含 `maxLatencyNanos`），
用于单测与简单本地观测，不建议作为生产监控（无分位、无维度）。

实现注意：钩子在**多线程热路径**被频繁调用，必须线程安全（用 `LongAdder` / `AtomicLong` / Micrometer 计数器）。
